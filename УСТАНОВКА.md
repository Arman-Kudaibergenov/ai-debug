# AI_Debug 1.2.0 — установка и подключение поддержки

Расширение 1С с HTTP-API для ИИ-диагностики и точкой обращений пользователей
(чат с автодосье, скриншоты, голос, ответы ИИ-воркера).

## Требования

- Платформа 8.3.24 или новее.
- Конфигурация на БСП (для назначения роли через профили групп доступа).
- Публикация базы на веб-сервере (для API и веб-клиента).

## 1. Установка расширения

Через конфигуратор: Все функции → Расширения конфигурации → Добавить из файла
`AI_Debug_120.cfe`. После добавления:

- **снять флаг «Безопасный режим»** (иначе не работают запись обращений и чтение ТЖ);
- активность — включена, режим «Использовать в основных ролях» — как у остальных.

Через ibcmd (серверный вариант):

```bash
ibcmd infobase --data=/tmp/ibcmd-data --db-server=<pg> --db-name=<база> --dbms=PostgreSQL \
  --db-user=<dbuser> --db-pwd=<dbpwd> config load --extension=AI_Debug AI_Debug_120.cfe \
  --user=<пользовательИБ> --password=<пароль>
ibcmd infobase ... config apply --extension=AI_Debug --force --user=... --password=...
ibcmd infobase ... config extension update --name=AI_Debug --safe-mode=no --user=... --password=...
```

После apply перезапустить рабочие процессы (rphost) — иначе новые таблицы
расширения не видны сеансам (ошибка SDBL «нет таблицы ReferenceNNNN»).

## 2. Публикация HTTP-сервиса

При публикации базы на веб-сервере включить «Публиковать HTTP-сервисы расширений
автоматически» (в default.vrd: `<httpServices publishExtensionsByDefault="true">`).

Проверка (должен вернуть `"status": "healthy", "version": "1.2.0"`):

```bash
curl -u 'Пользователь:Пароль' http://<сервер>/<база>/hs/ai/health
```

## 3. Права пользователей (роль «AI: Обращения в поддержку»)

Вариант по UI (рекомендуется, 2 минуты на базу):

1. Администрирование → Настройка прав и пользователей → Профили групп доступа →
   создать профиль «AI: Поддержка», на вкладке «Роли» отметить
   **AI: Обращения в поддержку (AI_Поддержка)**.
2. Создать группу доступа «AI: Поддержка» с этим профилем и добавить пользователей.

Программный путь (если надо автоматизировать) — рецепт с порядком вызовов
(идентификаторы расширений → профиль → группа → СоставыГруппПользователей →
ОбновитьРолиПользователей) зафиксирован у нас в RLM-факте 28194dfd.

Пользователю дополнительно нужны: роль запуска клиента (тонкий/веб) и базовые
права БСП — как у обычного рабочего профиля.

## 4. Подключение ИИ-воркера

На сервере воркера (jefest, /opt/ai-support/config.json) добавить базу:

```json
"arenzapro": {
  "url": "http://<сервер>/<база>",
  "user": "<служебный пользователь>",
  "password": "<пароль>",
  "peers": ["<связанная база, если есть интеграция>"]
}
```

и `systemctl restart ai-support-worker`. Воркер сам заберёт новые обращения.
Служебному пользователю нужна роль AI_Поддержка (п.3) либо полные права.

## 5. Технологический журнал (опционально, для диагностики «тормозит/виснет»)

Положить в `<платформа>/conf/logcfg.xml` (пример — лёгкий набор событий, ~6 часов
хранения в /tmp/tj) и перезапустить рабочие процессы:

```xml
<config xmlns="http://v8.1c.ru/v8/tech-log">
	<log location="/tmp/tj" history="6">
		<event><eq property="name" value="EXCP"/></event>
		<property name="all"/>
	</log>
	<log location="/tmp/tj" history="6">
		<event><eq property="name" value="DBPOSTGRS"/><gt property="duration" value="2000000"/></event>
		<property name="all"/>
	</log>
	<log location="/tmp/tj" history="6">
		<event><eq property="name" value="TLOCK"/></event>
		<event><eq property="name" value="TTIMEOUT"/></event>
		<event><eq property="name" value="TDEADLOCK"/></event>
		<property name="all"/>
	</log>
</config>
```

## 6. Как пользователь создаёт обращение

- Раздел «AI: Поддержка» → «Сообщить о проблеме (AI)» — чат.
- Контекст объекта: в объекте «Ещё → Получить ссылку», в чате Ctrl+V в большую
  зону — ссылка сама встаёт в поле (туда же Ctrl+V скриншота — во вложения,
  кнопка «Запись голоса» — голосовое сообщение, расшифруется автоматически).
- Ответ ИИ появляется в чате сам (опрос каждые 15 секунд).

## Проверочный цикл после установки

```bash
# создать обращение
curl -u 'U:P' -X POST http://<srv>/<base>/hs/ai/support/create \
  -H 'Content-Type: application/json' -d '{"subject":"Тест","text":"Проверка"}'
# оно должно появиться в pending, а воркер — ответить (статус Отвечено)
curl -u 'U:P' http://<srv>/<base>/hs/ai/support/pending
```
